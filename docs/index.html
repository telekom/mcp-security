Defense Principles Abwehrprinzipien

1

Zero Trust for Tool Outputs Zero Trust für Tool-Ausgaben

Sanitize every tool response before feeding it to the LLM context. Jede Tool-Antwort bereinigen, bevor sie dem LLM-Kontext zugeführt wird.

2

Least Privilege Least Privilege

Each MCP server gets only the permissions it needs — no cross-server authority. Jeder MCP-Server erhält nur die nötigen Berechtigungen — keine serverübergreifende Autorität.

3

Human in the Loop Human in the Loop

Further Challenges Weitere Herausforderungen

More Structural Problems Weitere strukturelle Probleme

⚡ Elicitation ⚡ Elicitation

Requires interactive user input — headless agents running unattended cannot respond to elicitation requests. Erfordert interaktive Benutzereingaben — Headless-Agents, die unbeaufsichtigt laufen, können Elicitation-Anfragen nicht beantworten.

🔄 Sampling 🔄 Sampling

Reverts the client-server architecture — the server calls back into the client LLM, bypassing all control and audit mechanisms. Kehrt die Client-Server-Architektur um — der Server ruft das Client-LLM zurück und umgeht dabei alle Kontroll- und Audit-Mechanismen.

📌 Sessions 📌 Sessions

Requires stateful implementations and sticky routing in the proxy — problematic for high availability and load balancing. Erfordert zustandsbehaftete Implementierungen und Sticky-Routing im Proxy — schwierig für High Availability und Load-Balancing.

🔍 JSON-RPC Routing 🔍 JSON-RPC-Routing

Requires payload inspection to route requests — unlike REST APIs where the URL alone determines the route. Erfordert Payload-Inspektion für das Routing — anders als bei REST-APIs, bei denen die URL allein die Route bestimmt.

MCP Server Cards (SEP-2127) MCP Server Cards (SEP-2127)

Signed manifests prevent rug pulls — servers can no longer silently swap their tool list after being trusted. Signierte Manifeste verhindern Rug Pulls — Server können ihre Tool-Liste nach Vertrauensvergabe nicht mehr heimlich austauschen.

🔀

HTTP Streamable Transport (SEP-2243) HTTP Streamable Transport (SEP-2243)

Standard HTTP transport enables proper middle boxes — proxies and gateways can route MCP traffic without payload inspection. Standardisierter HTTP-Transport ermöglicht echte Middle Boxes — Proxies können MCP-Traffic routen ohne Payload-Inspektion.

🏢

Enterprise-Managed Authorization (SEP-990) Enterprise-Managed Authorization (SEP-990)

Enterprises centrally control which MCP servers users may access. Via IdP authentication and ID-JAG token exchange, access is granted automatically — without manual approval per server. Unternehmen steuern zentral, auf welche MCP-Server Nutzer zugreifen dürfen. Über IdP-Authentifizierung und ID-JAG-Token-Austausch wird der Zugriff automatisch gewährt — ohne manuelle Freigabe pro Server.

Takeaways Fazit

Three Things to Remember Drei Dinge zum Merken

1

MCP is powerful and insecure by default. The protocol delegates security entirely to the implementation. MCP ist mächtig und standardmäßig unsicher. Das Protokoll delegiert Sicherheit vollständig an die Implementierung.

2

All MCP content is prompt input. Sanitize it. Same principles as SQL injection prevention — applied to LLM context. Alle MCP-Inhalte sind Prompt-Eingaben. Bereinige sie. Gleiche Prinzipien wie SQL-Injection-Schutz — angewendet auf den LLM-Kontext.

3

Build a security layer, not just security checks. A proxy between agent and servers enforces policy centrally. Baue eine Sicherheitsschicht, nicht nur Sicherheitsprüfungen. Ein Proxy zwischen Agent und Servern setzt Richtlinien zentral durch.
